# 입력 계약 (단위·좌표계·레이어·선박 조건)

> 멘토링 1차 확인 항목 2: "픽셀·mm·m 단위, 좌표계, 선종·흘수 조건의 입력 계약"
> 구현: `engine/garc/contract.py` · 테스트: `engine/tests/test_contract_session.py`

## 1. 대상 도면
- **GA 측면도(Profile, 중심선 단면) 1장**을 모델 공간에 그린 2D 도면. 평면도·정면도는 MVP 범위 밖.
- 실제 GA(한 시트에 측면도·평면도·단면도, mm 시트에 1/1000, GA_ 레이어 없음)는 §11 **실도면 연결**(축척·측면도 영역·역할 지정)로 연결한다 — 레이어를 옮기지 않는다.
- 이미지(픽셀)·PDF 스캔 도면은 **받지 않는다.** 픽셀은 축척 근거가 없어 거리 판정에 쓸 수 없다. 이미지 GA는 AutoCAD에서 다시 그린 뒤 검사한다.

## 2. 단위
| 경로 | 단위 결정 | 모르면 |
|---|---|---|
| DWG/DXF 좌표 | `$INSUNITS` (4=mm, 5=cm, 6=m) 또는 특성 `GARC_UNITS`=mm/cm/m | **모든 규칙 '검토 불가'** (추측하지 않음) |
| 도면 특성 길이값 (LOA, L, AP·FP 위치, 흘수) | 항상 **m** | — |
| 엔진 내부 | 항상 **m**, 소수 6자리(1 µm) 반올림 | — |

추가 안전장치(가시거리 '검토 불가'): 도면 선체 길이(GA_HULL의 x 범위)가 LOA와 2%(최소 0.5 m) 넘게 다르거나, AP·FP가 선체 x 범위(같은 허용차) 밖이거나, 조종위치가 선수 끝보다 앞이면 멈춘다. mm 도면을 m로 잘못 선언하거나 LOA·AP·FP 자릿수를 틀리면 여기서 걸린다. **이 대조는 'LOA < 55 m 적용 제외' 판단보다 먼저** 한다(LOA 오타가 '적용 제외 → 초록'으로 새지 않게).

값 검증(전 규칙 '검토 불가'):
- `SHIP_VALUE_INVALID` — `GARC_LOA`·`GARC_L_LL`은 0보다 큰 유한값, `GARC_X_AP`·`GARC_X_FP`·`GARC_Z_BASE`는 유한값, `GARC_EYE_HEIGHT`는 0~5 m. `nan`·`inf`처럼 숫자로 읽히지만 뜻이 없는 값, 1800(mm로 입력한 눈높이) 같은 값도 여기서 멈춘다.
- `SHIP_VALUE_MISMATCH` — `GARC_L_LL`이 LOA + 허용차(2 %, 최소 0.5 m)보다 길거나 LOA의 0.5배보다 짧으면(1320·13.2 같은 자릿수 오타) 멈춘다. `GARC_LBP`가 있으면 AP–FP 간격과 LBP가 허용차(2 %, 최소 0.5 m) 넘게 다를 때도 멈춘다(축척·기준점 실수).
- 위 범위(5 m, 0.5배)는 **오타·단위 실수 감지용 넓은 범위이지 규정값이 아니다.**
- 흘수 조건의 NaN·음수는 `CONDITION_RANGE`(가시거리 '검토 불가').
- **숫자 형식**: 도면 특성·흘수는 십진수만 받는다(`140`, `1.4e2`, `+140`, `140.`). `nan`·`inf`·`1_40`·전각 숫자(`１４０`)·쉼표 소수점(`140,0`)은 숫자로 보지 않는다(`PROP_INVALID`/`CONDITIONS_INVALID`).
- **중복 키**: `GARC_LOA`와 `garc_loa`처럼 대소문자만 다른 키가 서로 다른 값이면 `PROP_DUPLICATE`(전 규칙 '검토 불가').

가시거리 규칙의 추가 대조(오타 감지용, 규정값 아님 — 걸리면 가시거리 '검토 불가'):
- 조종위치(GA_EYE) x가 선체 x 범위(후단 − 허용차) ~ 선수 끝 사이, 높이가 기선 + 0.5·LOA 이하.
- 기선(`GARC_Z_BASE`)이 도면 선체 **중앙부 바닥**보다 허용차(2 %·LOA, 최소 0.5 m) 넘게 높지 않음. 중앙부 바닥 = AP~FP 가운데 절반 구간 21점에서 선체 윤곽과 만나는 가장 낮은 z들의 **중앙값**. 선미 스케그·레이크드 킬·선수 포어풋이 있어도 막히지 않게 중앙부만 보고, 선체를 위쪽만 그렸어도 걸리지 않게 '높은 쪽'만 본다.
  - 약해지는 경우: 중앙부 바닥선이 절반 이상 그려져 있지 않으면 이 대조는 약해진다 — GA_HULL에 용골선(바닥)까지 그릴 것.
  - 막히는 정상 도면: 기선보다 허용차 넘게 깊은 구조(긴 스케그, 기선을 선수 용골에 둔 큰 레이크드 킬, 계단 용골)가 **중앙부 구간의 절반 넘게** 걸치면 '검토 불가'가 된다. 이런 선형은 기선을 중앙부 용골 높이에 두고 흘수를 그 기준으로 입력한다.
- 모든 흘수 조건에서 기선 + 흘수 ≤ 도면 선체 최고점 z.
- 기선이 도면 **선체 최저점**보다 허용차 넘게 아래면 멈춘다(입력값이든 기본값 0이든). 원점이 기선이 아닌 실도면에서 기선을 안 넣었거나 `GARCSETUP`의 0이 남아 수선이 배 아래로 내려가 통과로 새는 경로를 막는다. 선체 윤곽에 바닥(용골)선이 하나도 없으면 정상 도면도 여기서 멈춘다 — 선체에 바닥선을 포함할 것.
- 용골 거치일은 `YYYY-MM-DD` 형식만(Python 버전마다 다른 해석 방지), 1950-01-01 이전이면 오타로 보고 멈춤(적용 제외로 넘기지 않음). 1950~1998-06-30은 정상 적용 제외이며, 이때 전체 문구에 "적용 제외 n건 — 적용 조건 입력 확인"을 붙인다.
- 감지 못 하는 오타: 선체 안의 다른 x로 잘못 찍은 조종위치(예: 18 → 118), 범위 안의 흘수 오타(8 → 9). 도면 위 표시(조종위치 원·수선)로 사람이 확인한다.

## 3. 좌표계
- **X = 선수 방향 +, Y = 위 +** (도면 그대로의 WCS).
- 원점은 자유. 대신 도면 특성에 **같은 좌표계의 m 값**으로 `GARC_X_AP`, `GARC_X_FP`, `GARC_Z_BASE`(기선 높이)를 적는다.
- `GARC_X_FP ≤ GARC_X_AP`면(좌우 반전 도면) 전 규칙 '검토 불가'.
- 엔진은 오프셋 변환 없이 `m = 도면값 × 단위배율`만 한다 → 플러그인이 시선·허용선을 도면에 되돌려 그릴 때 `÷ units_scale`만 하면 된다.

## 4. 레이어 → 역할
| 레이어 | 역할 | 그리는 것 | 쓰는 규칙 |
|---|---|---|---|
| `GA_HULL` | hull | 선체 측면 윤곽 (선수재, 선수루 갑판, 불워크 상단 포함) | 가시거리: 장애물 + 선수 끝(x 최대값) |
| `GA_EYE` | eye | **조종위치의 선교 갑판 높이 점 1개** (POINT 또는 블록 삽입점). 선·폴리선이면 '검토 불가'(`EYE_SHAPE`) | 가시거리 |
| `GA_OBST` | obstruction | 선교 앞 장애물 측면 윤곽 — 갑판 화물(적재 최대 높이), 크레인, 마스트, 해치커버 | 가시거리 |
| `GA_BHD_COLL` | collision_bhd | 충돌격벽 선 (계단형이면 **폴리선 하나**로) | 충돌격벽 |
| `GA_BULB` | bulb | 수선 아래 FP 앞 돌출부(구상선수) 윤곽 | 충돌격벽 기준점 |

- 지원 객체: LINE, LWPOLYLINE, POLYLINE(2D·3D), POINT, INSERT, ARC·CIRCLE(추출기가 점 + bulge로), ELLIPSE·SPLINE(추출기가 촘촘한 꺾은선으로 — 곡선 크기의 1/10000 수준). 그 외(해치, 메시, 표 등)가 GA_ 레이어에 있으면 해당 규칙을 '검토 불가'로 표시한다(조용히 무시하지 않음).
- **블록(INSERT)**: GA_EYE에서는 삽입점 = 조종위치. 다른 GA_ 레이어·역할 지정 블록은 **추출기가 펼쳐서**(중첩 포함, 블록 안 문자·치수·해치 제외) 하위 형상을 보낸다 — handle `<블록 handle>.<번호>`, `block` = 블록 handle(2026-10-18, 그 전에는 '검토 불가'였음). 펼칠 수 없는 블록(비균일 축척 등)은 삽입점만 보내 '검토 불가'.
- 좌표가 하나도 없는 객체는 '검토 불가'(`ENTITY_EMPTY`).
- 폴리선의 호(bulge)는 엔진이 **호에 외접하는 꺾은선**(이웃 접선의 교점)으로 바꾼다(|bulge| ≤ 1e-9는 직선). 꺾은선은 항상 호의 볼록한 바깥쪽에 있고 호에서 **0.1 mm 이내**다(분할 수는 반지름에 맞춰 정함, 한 구간 최대 10°, 호 하나당 최대 512구간 — 상한에 걸리면 근사가 거칠어지지만 여전히 바깥쪽). 그래서 장애물 그림자를 작게 보지 않는다(안전 쪽). 반대로 선수 끝·격벽 위치처럼 '앞쪽 끝'을 쓰는 값은 최대 0.1 mm 앞으로 잡힐 수 있다.
- 닫힌 폴리선은 마지막→처음 구간도 포함. 스플라인 맞춤 폴리선의 제어점은 곡선 위가 아니므로 쓰지 않는다.
- 호 분할 후 전체 좌표가 **15만 점**을 넘으면 형식 오류(검토 불가)로 멈춘다 — 응답이 플러그인 제한 시간(3 s)을 넘기지 않게. 둥근 모서리 장애물 1000개 ≈ 10만 점, 계약+판정 0.6 s(2 vCPU 기준).
- 좌표는 WCS 기준. 폴리선·블록의 OCS(돌출 방향 −Z)는 추출기가 WCS로 바꿔 보낸다 — dxf.py는 ezdxf로 변환·테스트, Extractor.cs는 `GetPoint3dAt`·`Polyline2d.VertexPosition`(**빌드·실기 확인 필요**).
- 레이어 이름은 앞뒤 공백을 무시하고 대소문자를 구분하지 않는다(플러그인·DXF 둘 다). GA_ 이외 레이어는 읽지 않는다 — `GARCSETUP`으로 만든 레이어를 쓸 것.
- **비슷한 레이어 이름은 멈춘다**: 추출기가 모델 공간 레이어별 객체 수(`layer_counts`)를 보내고, 엔진은 이름을 NFKC 정규화(전각 → 반각)·대문자·영숫자만으로 바꿔 비교한다. 정식 이름으로 **시작**하거나(`GA-OBST`, `GA_OBST_CRANE`, `GA_OBSTRUCTION`), 5자 이상이면서 정식 이름의 **앞부분**이거나(`GA_BHD`, `GA_OBS`), 5자 이상이고 'GA'로 시작하면서 **한 글자만 다르면**(`GA_0BST`, 키릴 문자 1자 섞임 — 2자 이상 섞이면 못 잡음; `GA_FULL`·`GA_BULK`처럼 실제로 다른 뜻의 이름도 걸리므로 이런 이름은 쓰지 말 것) 그 레이어에 객체가 있을 때 해당 역할 규칙을 '검토 불가'(`LAYER_NEAR_MISS`)로 멈춘다. 객체 수를 해석할 수 없으면 '있음'으로 본다. `GA_REF`·`GA_DIM`·`GA_TEXT`처럼 다른 이름은 영향 없음 — 보조선은 이런 이름을 쓸 것. 감지 못 하는 예: `GA_O`(5자 미만), `장애물`, 그리고 **'GA' 접두 자체가 깨진 이름**(`G_OBST`, 키릴·그리스 문자로 쓴 G·A, `0GA_OBST`) — 이런 레이어의 객체는 조용히 빠지므로 `GARCSETUP`으로 만든 레이어만 쓸 것.
- 플러그인은 정규화했을 때 'GA'로 시작하는 레이어의 객체가 바뀌어도 다시 검사한다(신호만, 판단은 엔진). 엔진이 멈추는 비슷한 이름은 모두 이 범위 안이다.

## 5. 도면 특성 (DWGPROPS → 사용자 정의)
| 키 | 의미 | 예 | 없으면 |
|---|---|---|---|
| `GARC_LOA` | 전장 LOA [m] — SOLAS V/2.4 '길이' | 140 | 가시거리 na |
| `GARC_L_LL` | 만재흘수선협약 길이 L [m] — SOLAS II-1/2 | 132 | 충돌격벽 na |
| `GARC_X_AP` / `GARC_X_FP` | AP·FP의 도면 x [m] | 0 / 132 | 해당 규칙 na |
| `GARC_Z_BASE` | 기선의 도면 y [m] | 0 | 0 |
| `GARC_EYE_HEIGHT` | 선교 갑판 위 눈높이 [m] | 1.8 | 1.8 |
| `GARC_KEEL_LAID` | 용골 거치일 | 2026-03-02 | 1998-07-01 이후 건조로 가정 (근거에 기록) |
| `GARC_CONDITIONS` | 흘수 조건 `이름:선미흘수/선수흘수; …` [m, 기선 기준, AP·FP 위치] | `만재 출항:8.0/8.0; 밸러스트 도착:6.5/4.0` | 가시거리 na |
| `GARC_UNITS` | `$INSUNITS` 대신 단위 강제 | mm | — |
| `GARC_SHIP_TYPE` | 선종 (현재 판정에 미사용, 기록용) | general_cargo | — |
| `GARC_SCALE` | 도면 축척 1/N — 시트에 1/N로 그린 도면(도면 1단위 = 단위 × N). N 범위 1~10000, 형식 오류면 전 규칙 '검토 불가' | `1/1000` | 1 |
| `GARC_LBP` | 수선간 길이 LBP [m] — 참고값. AP–FP 간격과 대조 | 219 | 대조 안 함 |
| `GARC_REGION` | 측면도 영역 `x0,y0,x1,y1` (**도면 단위**) — 레이어 단위 역할을 이 안의 객체로만 | `100,195,330,262` | — |
| `GARC_LAYER_ROLES` | 레이어 단위 역할 `레이어=역할; …` (역할: 선체·장애물·충돌격벽·구상선수 또는 hull·obstruction·collision_bhd·bulb, 조종위치는 불가) — `GARC_REGION`과 함께만 | `컨테이너=장애물` | — |

## 6. 판정 상태
| 상태 | 뜻 | 화면 |
|---|---|---|
| pass | 규칙 후보 기준 충족 | 파랑(v0.4부터, 전에는 초록) + "최종 판단은 설계자 검토" |
| fail | 위반 | 빨강 + 대상 객체 표시 + 수치 제안 |
| na | 입력 누락 | 주황 |
| review | 조건 밖·모순·모호 (단위 불명, 조종위치 2개, LOA 불일치, 지원 안 되는 객체, 펼칠 수 없는 블록, NaN·0 이하 값, 좌표 없는 객체 …) | 주황, "사람 확인" |
| skip | 적용 대상 아님 (LOA < 55 m 등) | 회색 |

**전체 결과**: fail > incomplete(na·review가 하나라도) > pass. 일부만 통과한 상태를 충족(파랑)으로 보여주지 않는다.

## 7. raw JSON (플러그인·DXF → 엔진)
```json
{
  "schema": "garc.raw/1",
  "source": {"app": "AutoCAD 25.0", "file": "S140.dwg", "doc_id": "{GUID}"},
  "insunits": 4,
  "props": {"GARC_LOA": "140", "GARC_CONDITIONS": "만재 출항:8.0/8.0"},
  "entities": [{"handle": "9A", "layer": "GA_OBST", "type": "LWPOLYLINE",
                "points": [[100000, 13500], [100000, 24000], [112000, 24000], [112000, 13500]],
                "bulges": [0, -0.4142, 0, 0], "closed": false}]
}
```
- `bulges`(선택): 꼭짓점 i→i+1 구간의 bulge = tan(중심각/4), 양수 = 반시계. 꼭짓점 수와 같아야 하며 아니면 계약 오류(400). 호가 없으면 생략.
- `closed`(선택): 닫힌 폴리선이면 true.
- `layer_counts`(선택): `{"레이어 이름": 객체 수}` — 비슷한 레이어 이름 감지용. 판단은 엔진이 한다.

`handle`은 AutoCAD 객체 핸들(16진). Undo로 지웠다 되살린 객체도 같은 handle을 유지하므로 revision diff의 기준이 된다.

`doc_id`(엔진 세션 키)는 플러그인이 `FingerprintGuid:문서별 GUID`로 만든다. 같은 원본에서 복사한 도면은 FingerprintGuid가 같으므로(샘플 S140_rev0~4도 동일) 그것만으로는 구분되지 않는다.

엔진 서버는 Host가 루프백(127.0.0.1·localhost·[::1])이고 `Origin` 헤더가 없는 요청만 받는다(그 외 403).

## 8. 요소별 판정 (`results[].elements`, 엔진 0.3.0)
마우스 오버 툴팁·체크리스트·로고 배지가 쓰는 객체 단위 판정. **판정은 엔진만** — 플러그인은 그대로 보여 준다.
```json
{"element_id": "9A", "rule_id": "SOLAS-V-22.1.1", "rule_name": "선교 전방 수면 가시거리",
 "role": "obstruction", "role_ko": "장애물", "status": "fail",
 "required": "상단 z ≤ 22.45 m (x=112.00 m 지점, 입력된 모든 흘수 조건)",
 "actual": "z = 24.00 m (이 객체만으로 사각 433.84 m > 허용 280 m)",
 "diff": "1.55 m 초과", "guide": "x=112.00 m 지점 상단을 z=22.45 m 이하로 낮추세요", "margin": -1.55}
```
- `status`는 **pass / fail / unknown** 셋. 규칙이 입력 누락(na)·검토 불가(review)면 그 규칙이 읽는 객체는 모두 `unknown`(⚠ 확인 필요) — 판정 안 된 객체가 충족으로 보이지 않게.
- 가시거리: 객체마다 '이 객체 하나만으로' 사각 거리 기준을 넘는지를 규칙과 **같은 계산**으로 본다 → 규칙이 위반이면 위반 객체가 반드시 하나 이상, 충족이면 없다(무작위 400건 테스트). 선교 뒤 객체는 "전방 시야와 무관"으로 충족. 조종위치는 판정의 기준점이라 위반 개수에 넣지 않고 참고값(이 눈높이의 사각 거리)만 보여 준다.
- 충돌격벽: 격벽 객체 하나 — 기준점에서의 거리 구간과 허용 구간, 하한·상한 차이.
- 적용 제외(skip) 규칙은 요소 판정을 내지 않는다.

## 9. 버전 비교 (`POST /v1/compare`, `python -m garc compare A B`)
요청 `{"a": raw, "b": raw, "labels": ["v1", "v2"]}` → 응답 주요 필드:
| 필드 | 뜻 |
|---|---|
| `changes[]` | 변경 항목: `number`(① …, 선미→선수, 형상 없는 선박 정보·흘수 조건은 끝), `kind`(added/removed/modified/ship/conditions), `element_id`, `desc_ko`(예: "충돌격벽 위치 x 122.50 m → x 124.50 m (기준점에서 11.00 m → 9.00 m)"), `before_ko`/`after_ko`, `resolved[]`/`introduced[]`(이 변경으로 해결·발생한 위반 — '해결'은 이후가 **충족이거나 객체가 삭제**된 경우만), `needs_check[]`(이 변경으로 판정 못 함·입력 누락·적용 제외로 바뀐 것 — 해결로 세지 않고 '확인 필요'. 위반 객체를 지웠는데 그 규칙을 판정할 수 없게 된 경우도 여기. 선박 정보 여러 개가 함께 바뀌면 원인을 단정하지 않고 '중 원인 확인'을 붙인다), `related_rules`, `center`/`bbox`(m) |
| `indirect[]` | 바뀌지 않은 객체인데 판정이 바뀐 것(예: 선교를 높여 앞 컨테이너 위반이 해결, 블록이 들어와 판정 못 함으로 바뀜) — 특정 변경에 붙이지 않고 따로. 판정 못 함으로 바뀐 것은 규칙마다 한 줄로 묶는다(`element_ids`, `count`) |
| `resolved_rules[]`/`introduced_rules[]`/`needs_check_rules[]` | 규칙 수준 변화(위반 해결 / 새 위반 / 판정 못 함·적용 제외로 바뀜) |
| `violations` | 미충족 요소 수 `{"before", "after"}` |
| `unknown` | 확인 필요(판정 못 함) 요소 수 `{"before", "after"}` |
| `a`/`b` | 각 버전 요약(전체 판정, 규칙별 상태, 미충족·확인 필요 요소 수) |
| `geometry.a`/`geometry.b` | 두 버전 객체 형상(m, 호는 분할됨) + 요소 상태 — 비교 창·내보내기가 그대로 그린다 |
| `bounds`, `units_scale`, `same` | 그림 범위(m), 도면 단위 배율, 변경 없음 여부(형상·선박 정보가 같고 **판정도 같을 때만** 참 — 비슷한 레이어 이름 등으로 판정만 바뀌면 거짓) |

handle이 같으면 같은 객체로 본다(AutoCAD는 Undo·저장 후에도 handle 유지). 객체를 지우고 같은 모양으로 다시 그리면 '삭제 + 추가'로 나온다.

## 10. 버전 기록 폴더 (플러그인, `<도면이름>.garc\`)
도면을 저장할 때(또는 `GARCVERSION`) 플러그인이 도면 옆에 쓴다. 저장 안 된 도면은 `내 문서\GaRuleCheck\<이름>.garc\`.
```json
{"schema": "garc.versions/1", "drawing": "S140_v2_fixed.dxf",
 "versions": [{"version": 1, "file": "v1.raw.json", "created": "2026-10-20T10:12:00", "author": "표인범",
               "reason": "other", "reference": "", "note": "…", "overall": "fail", "fail_elements": 3, "hash": "…"}]}
```
- `reason`: `rule_violation`(규정 위반) / `feedback`(피드백) / `other`(기타). `reference`: 관련 규정 조항 또는 피드백 내용.
- `v{n}.raw.json`: 그때의 raw 스냅샷(§7 형식) — **GA_ 레이어 좌표가 들어 있으므로 도면과 같은 보안 등급**. 저장소 `.gitignore`가 `*.garc/`를 막는다(데모 `samples/S140_*.garc/`만 예외).
- `hash`: 객체·특성 지문. 마지막 버전과 같으면 새 버전을 만들지 않는다.
- 도면 번호(생산팀 전달 머리말): 도면 특성 `GARC_DWG_NO`, 없으면 파일 이름.


## 11. 실도면 연결 (엔진 0.4.0 · 플러그인 0.5.0, 2026-10-18)
실도면 5건(mm 시트에 1/1000, 원점 ≠ AP·기선, GA_ 레이어 없음, 한 시트에 여러 뷰, 컨테이너·크레인이 블록)을 레이어를 바꾸지 않고 검사하기 위한 계약.

**객체별 역할(`entities[].role`)** — 레이어보다 우선. `hull`·`obstruction`·`collision_bhd`·`bulb`·`eye` 또는 한글(선체·장애물·충돌격벽·구상선수·조종위치). 모르는 역할은 `ENTITY_ROLE_UNKNOWN`(검토 불가).
- 플러그인은 역할을 도면 사전(NOD)의 XRecord **`GARC_ROLES`**에 `(1, 역할)` 다음 `(330, 객체)`를 반복해 저장한다(`RoleMap.cs`). 도면 데이터이므로 Undo·저장에 묶인다. DXF 어댑터도 같은 XRecord를 읽는다.
- 역할 결정 순서: 객체 역할 > GA_ 레이어 > `GARC_LAYER_ROLES`.

**레이어 단위 역할 + 측면도 영역** — `GARC_LAYER_ROLES`의 레이어 객체 중 **점이나 선분이 영역에 걸친 것**만 쓴다(경계에 걸친 장애물을 버리지 않음). 영역을 둘러싸기만 하는 객체(도면 테두리)는 넣지 않는다. 영역 없이 쓰면 `LAYER_ROLES_INVALID`(검토 불가) — 같은 레이어가 평면도에도 있기 때문. 객체별 역할·GA_ 레이어에는 영역을 적용하지 않는다.

**준비 상태(`/v1/check` 응답 `readiness`)** — 판정에 필요한 입력을 한 번에(규칙은 첫 누락에서 멈추므로):
```json
{"ready": 8, "total": 10, "all_ready": false,
 "items": [{"key": "l_ll", "name_ko": "L (만재흘수선협약 길이)", "required": true, "rules": ["SOLAS-II1-12"],
            "status": "missing", "value_ko": null, "hint_ko": "선급 계산서의 L — …", "problem_ko": null}, …],
 "problems_ko": ["…계약 문제 전부…"]}
```
상태: `ok` / `missing` / `invalid` / `default`(기본값 사용 — 기선 0, 눈높이 1.8 m) / `optional`. 필수: 단위·축척, LOA, L, AP, FP, 기선, 흘수 조건, 선체 윤곽, 조종위치, 충돌격벽. 계약 문제가 하나라도 있으면 `all_ready`는 거짓.

**주요 치수표 읽기(`POST /v1/particulars {"texts": [{"text", "x", "y", "h"}]}`, `python -m garc particulars a.dxf`)** — 도면 TEXT/MTEXT에서 LOA·LBP·형폭·형심·설계/구조 흘수·축척·선종 **후보**를 결정론(정규식 + 같은 줄/같은 줄 번호 짝짓기)으로 찾는다. AI·외부 전송 없음. 값이 둘 이상이면 고르지 않는다(`conflict`). `suggested_props`는 LOA·LBP·축척만, `suggested_conditions`는 설계·구조 흘수의 등흘수 조건 후보. **L(ICLL)·밸러스트 흘수는 GA에 없으므로 찾지 않는다**(사람 입력).

**블록 하위 객체** — `block` 필드가 있는 객체(펼친 블록)는 제안 문구에서 '블록 1F3(하위 n개)'로 묶이고, 버전 비교에서는 블록·종류마다 한 항목(`members` = 하위 handle 목록)으로 묶인다.

**제한 시간** — 플러그인 검사 요청은 좌표 2만 점마다 1초를 더한다(3 s → 최대 20 s). 실도면 시험(탱커 GA, 장애물 7천여 객체·좌표 6만 점)에서 엔진 계약+판정 0.3 s, 응답 JSON 약 4 MB.
