# 2026-10-18 기능 3종 검증 기록 (플러그인 v0.4.0 / 엔진 0.3.0)

대상은 `1d3edfe..HEAD`이고, 다음 기능을 다룬다.
- 요소별 판정(elements)
- 버전 비교(/v1/compare)
- 버전 기록·비교 창·생산팀 전달
- 떠 있는 로고 패널
- 마우스 오버 하이라이트

작성은 Opus 5.5, 독립 검증은 Sonnet 5.5가 3차까지 했다. 모델 사용 규칙은 "기본 검증은 Sonnet, 수정은 재검증, 중요 변경은 2차까지"를 따랐다.

C# 확인은 **컴파일까지만**이다. Claude 작업 환경에서 사용자 PC의 AutoCAD 2027 DLL과 .NET 10 WindowsDesktop을 참조해 빌드했고, 커밋마다 오류 0·경고 0이었다. **AutoCAD 안에서의 동작은 미확인**이며, `autocad/README.md` 확인표 15~25로 사용자 PC에서 확인해야 한다.

## 1차 검증 (Sonnet, 1d3edfe..기능 커밋)

### 확인된 것
- 규칙 판정과 요소 판정이 일치한다(무작위 400건). 판정 못 한 규칙의 객체는 '확인 필요'로 채워진다.
- JSON의 `allow_nan=False`를 통과한다.
- 공간 인덱스(HitIndex)가 전수 탐색과 일치한다.
- DTO가 엔진 JSON(snake_case)과 맞는다.
- 문서가 동작과 맞는다.
- 커밋마다 빌드된다.

### HIGH 1건 — 수정함
버전 비교가 fail→unknown/skip/na를 **"위반 해결"**로 셌고, 판정만 바뀌어도 `same=True`였다.

수정 내용:
- '해결'은 이후가 충족이거나 객체가 삭제된 경우만 센다. 나머지는 `needs_check`('⚠ 확인 필요')로 낸다.
- `same`은 형상, 선박 정보, 규칙·요소 판정이 모두 같을 때만 참이다.
- `needs_check_rules`와 `unknown{before,after}`를 추가했다.
- 회귀 테스트: 블록(INSERT) 추가, LOA 140→14 오입력, 비슷한 레이어(GA-OBST), needs_check 키.

### MEDIUM 9건 — 모두 수정함
| # | 지적 | 수정 |
|---|---|---|
| 1 | 로고 원과 배지 원이 겹친 부분이 구멍(XOR)으로 빠짐 | `GraphicsPath(FillMode.Winding)` |
| 2 | 엔진 응답 없음·판정 불가일 때 배지가 비어 '문제 없음'처럼 보임 | 주황 '!' 배지와 "엔진 응답 없음"·"판정 불가 있음" 문구 |
| 3 | 패널이 접혀 있을 때 도면 탭을 바꾸거나 GARCOFF하면 배지가 이전 값으로 남음 | 패널 표시 여부와 무관하게 갱신 |
| 4 | Ctrl+.가 두 경로로 들어와 두 번 토글될 수 있음 | 200 ms 안의 중복 무시 |
| 5 | 비교 그림에서 휠 확대가 포커스 없이 안 먹음 | 마우스가 올라오면 포커스 |
| 6 | 버전 기록 기본값이 오래된 검사 결과 기준 | 3차에서 최종 형태로 정리(아래) |
| 7 | 선박 정보·흘수 조건 변경에 규칙 수준 변화가 중복으로 붙음 | 규칙마다 한 번 |
| 8 | 극단 확대 시 GDI+ 오류 | 확대 범위 제한과 그리기 예외 처리 |
| 9 | 비교 창 표시·이동이 '활성 도면' 기준 | 창을 연 도면 기준. 도면을 닫으면 비교 창도 닫음 |

LOW 중 바로 고친 것:
- 다시 검사하면 hover 강조를 지운다.
- 내보내기 파일 이름의 점(.) 처리와 확장자를 보정한다.
- 머리말 값을 두 줄까지 감싼다.
- '미충족만 보기'에서 확인 필요만 남았을 때 주황으로 안내한다.
- README에 "저장 시 자동 기록은 GARC 감시 중일 때만"이라고 적었다.

## 2차 검증 (Sonnet, 수정 커밋 4개)

결과는 **진행 가능**이다. 지적 확인표에서 HIGH와 MEDIUM 1~5, 7~9는 ✅였다. 무작위 6000건과 이름 붙인 25건에서 "해결은 이후 충족 또는 삭제일 때만"과 "상태가 하나라도 다르면 same=거짓"이 모두 성립했다.

새 지적과 수정:

**MEDIUM — 버전 기록 직전의 무조건 재검사가 '해결' 전환을 지움.** 같은 입력으로 다시 검사하면 transitions가 비어서 기본 사유가 '기타'로 바뀌었다. 바뀐 것이 있을 때만 다시 검사하도록 고쳤다.

**LOW 7건 — 수정함:**
- 위반 객체를 지웠는데 그 규칙을 판정할 수 없게 되면, 해결이 아니라 확인 필요로 낸다.
- '입력 누락으로' 문구를 고쳤다.
- 판정 못 함으로 바뀐 간접 영향을 규칙마다 한 줄로 묶었다(LOA 오입력 하나로 객체 수백 줄이 나오던 문제).
- 선박 정보 대조 검사(L_LL↔LOA)로 막힌 규칙도 그 선박 정보 변경에 붙인다. 여러 값이 함께 바뀌면 "중 원인 확인"을 붙인다.
- 비교 요약을 (머리줄, 판정, 작성자)로 나눠 내보내기 머리말과 겹치지 않게 했다. 요약 높이는 자동이다.
- 비교 창의 도면이 활성 탭이 아니면 '도면에 표시'를 끄고 안내한다. 그 탭으로 돌아오면 다시 그린다.
- README에 배지 '!'와 확인 필요를 적었다.

## 3차 검증 (Sonnet, 2차 수정 커밋)

결과는 **MEDIUM 이상 없음**이다.
- 테스트 91건 OK.
- 무작위 4×1500건에서 불변식 위반 0.
- 빌드 오류·경고 0.
- 데모 비교: 미충족 3→0, 변경 4건, ✔ 3.

LOW 3건과 잔여 한계 1건을 모두 수정했다.
- 묶인 간접 영향의 `from`이 문자열 `"None"`으로 나오던 것을 null로 고쳤다.
- 마지막 검사가 실패했거나 감시 밖에서 선박 정보가 바뀐 경우에도 기록 직전에 다시 검사한다. 조건은 Dirty, 결과 없음, 스냅샷 지문 다름이다.
- 패널이 숨겨진 상태로 도면 탭을 바꿔도 다른 도면의 비교 표시를 지운다.
- (잔여 한계 해소) 버전 기록 창의 기본 사유·관련 조항은 '직전 검사 대비'가 아니라 **마지막 기록 버전과의 엔진 비교**로 정한다. 비교를 못 하면 검사 전환으로 대신한다.

## 남은 한계 (AutoCAD 실기에서 확인할 것)
- 마우스 오버의 `RawPoint`가 UCS를 돌린 도면에서 WCS와 어긋나는지(확인표 22, 23).
- 흑백 인쇄에서 노랑(변경) 선의 대비. 모양(점선·실선·◇)과 기호(~)로 구분되지만 실제 출력으로 확인해야 한다.
- hover throttle은 앞쪽만 처리한다. 커서를 빨리 움직이고 멈추면 마지막 위치 강조가 최대 40 ms 늦을 수 있다.
- 버전 지문(Fingerprint)은 C#이 계산한다. 같은 버전인지 판단하는 데만 쓰고 판정에는 쓰지 않는다.
- Ctrl+.는 한글 IME 상태에 따라 VK가 달라질 수 있다(확인표 18).
- 저장 시 자동 버전 기록은 그 도면을 GARC로 감시 중일 때만 동작한다(README에 명시).
